# Planner 对象模型示意图

对应 `docs/rfc/planner.md` v7 §3–§7、§10（决策 D60–D74）。三张图：对象关系与基本行为、执行会话的生命周期、一个典型流程中各对象如何协作。**清晰版请看 `docs/design/planner-object-model.html`**（手工排版的静态 SVG，浏览器直接打开）；下面的 mermaid 是同一内容的源码，GitHub 会自动排版，对象多时布局可能较乱。

v7 相对 v5 的变化：Planner 全局唯一，分层的是知识（懂你一份、懂系统按工作区分区）；工作区幕僚只是执行会话的一种用途；Planner 的介入按信任阶梯由你逐级放开；放行人只有你；新增承诺、早报与工作台面。

## 1. 对象关系与基本行为

- 实线箭头：主动动作（发出、派出、路由、记录）；虚线箭头：派生或依据（由什么得出、按什么判定）。
- 菱形：持有 / 包含（整体与部分）。
- 方框下半部分以 `+` 开头的是该对象的基本行为。

```mermaid
classDiagram
direction TB

class Owner["你"] {
  最终授权来源
  +发消息：默认发往焦点会话，或交给 Planner()
  +拍板卡片：批准 驳回 选择 回复()
  +一句话设置：频率 偏好 例行任务()
  +逐级放开信任阶梯、授予或撤销授权()
  +维护关注点 Now Next Not-now()
  +三级停止()
}

class Workbench["工作台面（视图）"] {
  文件 diff 预览 成品库 运行
  +你直接看、直接动这台机器()
  +你的操作记为"代表你本人"的状态变更()
}

class Gateway["网关（naozhi 本身，不用模型）"] {
  +路由：焦点会话 / Planner / IM 话题()
  +一秒内回执发给 Planner 的消息()
  +记录事件流、会话台账与健康状态()
  +动作前判权 hook，出错即拒绝()
  +需人决定：拒绝 + 一次性放行（放行人只有你）()
  +托管 L0：重试 自动继续 按建议执行（可撤回）()
  +推送管线：紧急 有时效 早报()
  +确定性早报()
  +三级停止()
}

class Planner["Planner（全局唯一）"] {
  模型：偏好表首个可用 · effort 自适应
  工具：只读 + naozhi MCP，无 Edit
  信任级别：只出意见 / 代办 / 指令 / 执行型主动
  +被唤醒：消息 事件 闹钟 承诺到点 外部来源巡检()
  +决定交给谁：通知已有 排后 取代 另开()
  +派出工作区幕僚做深度规划 / 评审()
  +预判（守护优先）、过程评审、复盘()
  +登记承诺，未闭环提醒()
  +叫停：先停下再告诉你()
  +提议：等你批准的计划()
  +合并处理系统性故障()
}

class UserModel["懂你（全局一份）"] {
  偏好（想听 别提 何时 形式）
  写作风格
  决定与先例（带出处，可被取代）
  关注点 Now Next Not-now
  节奏与打扰预算
  边界：需人决定清单（含每次确认）
  +只有你能改关注点 授权 边界()
  +一句话修改并回显()
  +没有隐形画像()
}

class Grant["授权"] {
  能力 范围 次数 过期
  来源：你确认的卡片
  +被引用于判权()
  +撤销()
}

class SystemModel["懂系统（按工作区分区）"] {
  全局：环境健康、承诺
  每个工作区：在途会话、关系、项目长期知识、外部产物
  +由事件流确定性派生()
  +接受 Planner / 工作区幕僚批注()
  +过期检测：锚点改了就标未复核()
}

class Workspace["工作区资料柜（按稳定 ID）"] {
  章程 例行任务 知识 路径锁
  +只有你能改章程()
}

class Commitment["承诺"] {
  内容 时间 关闭条件 状态
  +到点提醒，不受打扰预算挤压()
  +只有你能关闭()
}

class Session["执行会话（中立）"] {
  key：永久身份，不编码属性
  用途：普通 / 工作区幕僚 / 评审 / 侦察
  契约 血缘 产物 托管 污染（旁路文件）
  后端：Planner 派出与托管只用 Claude
  +接收消息并跑一个回合()
  +调用工具（每次经 hook 判权）()
  +必要时启动 CC Workflow 扇出()
  +给推荐项：可逆的按建议继续()
  +request_review / ask_planner()
  +交回结构化交接 或 不可完成()
  +停车 复活 归档()
}

class Message["消息"] {
  from：直接发送方
  on_behalf_of：代表谁
  origin：根来源，只降不升
  kind：请求 结果 意见 代办 指令 叫停 提问 提议 取消
  +你的：passthrough 直通 CC 队列()
  +Planner 的：网关信封，在回合边界投递()
  +决定这一轮按谁的权限执行（混合取最低）()
}

class Event["事件"] {
  回合 工作流 进程死亡 健康转移
  状态变更（push merge 发版 云写）
  你在工作台上的操作
  读入外部内容 环境异常 心跳
  +唤醒 Planner（经网关四级分流）()
  +给会话打污染标记()
  +汇入早报与离开摘要()
}

class InboxItem["收件箱条目（视图）"] {
  分组：等你处理 待审 答应你的 已解决
  +按三级推送到手机或浏览器()
  +只有你能关（通知可自动关闭）()
  +卡片过期即作废，从不默认放行()
}

class Helper["一次性助手（不是会话）"] {
  +新消息归属判断()
  +离开摘要()
  +一次性读取者：外部内容 → 结构化摘要()
}

Owner --> Message : 发出
Owner --> Workbench : 直接操作
Workbench ..> Event : 记为状态变更
Owner --> UserModel : 维护关注点 授权 边界
Planner "1" *-- "1" UserModel : 持有
Planner "1" *-- "1" SystemModel : 持有
SystemModel "1" *-- "N" Workspace : 按工作区分区
SystemModel "1" *-- "N" Commitment : 包含
UserModel "1" *-- "N" Grant : 包含
Planner --> Message : 发出 / 接收
Gateway --> Message : 路由
Message --> Session : 投递到
Planner "1" --> "N" Session : 派出 通知 取代 停车（含工作区幕僚）
Session --> Session : prev 接续
Gateway --> Session : 动作前判权
Grant ..> Gateway : 判权依据
Session "1" --> "N" Event : 产生
Gateway --> Event : 记录
Event ..> SystemModel : 派生
Event ..> Planner : 唤醒
Workspace ..> Planner : 触发例行任务
Message ..> InboxItem : 需要你时投影
Event ..> InboxItem : 需要你时投影
InboxItem --> Owner : 推送
Gateway --> Helper : 调用
```

## 2. 执行会话的生命周期

v7 未变。进程、上下文、记录分层回收，寿命跟产物走（RFC §5.2）。

```mermaid
stateDiagram-v2
direction LR
[*] --> 运行中 : 新开 或 复活
运行中 --> 保温 : 回合结束
保温 --> 运行中 : 新消息（缓存有效期内）
保温 --> 等待中 : 绑定产物，等审阅 / CI / 你
保温 --> 休眠 : 产物仍开着但无订阅
运行中 --> 停车 : 被抢占 或 被取代（先推送半成品）
等待中 --> 运行中 : 审阅意见 / CI 失败 / 你回复（满足复活条件）
休眠 --> 运行中 : 追问（满足复活条件）
停车 --> 运行中 : 资源回来 / 恢复条件满足
等待中 --> 已归档 : 产物关闭 + 24 小时
休眠 --> 已归档 : 空闲超时
停车 --> 已归档 : 被取代且产物已处置
已归档 --> [*]

note right of 休眠
  复活条件：同一产物、上下文约 100k 以内、
  休眠不超过 72 小时、版本不变、无污染；
  不满足就另开新会话 + 交接
end note
```

## 3. 典型流程：你交一个大任务后离开

```mermaid
sequenceDiagram
autonumber
actor 你
participant 网关
participant P as Planner
participant A as 工作区幕僚
participant S as 执行会话
participant 收件箱

你->>网关: "交给你：处理完剩下的 review issue，每个一个 PR，我出去一趟"
网关-->>你: 一秒回执："收到，交给 Planner"
网关->>P: 路由（代表你）
P->>P: 加载懂你 + naozhi 工作区分区，决定"另开"，写契约
P->>S: 派出 task:…（parent = Planner，托管开）
P->>收件箱: 登记承诺"全部合并后告诉你"
loop 每个回合
  S->>网关: 调用工具前 hook 判权（代表你 · 授权 · 污染）
  S-->>网关: 事件（回合结束 / 工作流阶段 / 状态变更）
end
S->>网关: 给出两种修法，推荐 A（可逆）
网关->>S: 2 分钟无人回应，按建议继续（标"可撤回"）
网关->>P: 唤醒：第一份 diff（大改动）
P->>A: 派出深度评审（干净上下文，只读）
A-->>P: 结论：在改症状，根因在出队顺序（附依据）
P->>S: 意见（信任级别 1：只出意见）
S-->>P: 接受并修改
网关->>P: 唤醒：PR 全部 CI 绿
P->>P: 预判：你过去合并后都发版，备好 changelog
P->>收件箱: 提议"发版 v0.1.46？"（每次确认）
收件箱->>你: 推送（紧急 · 可直接点按钮）
你->>收件箱: 批准（Face ID）
收件箱->>S: 一次性放行 + "已放行"
P->>P: 建议关闭承诺；复盘：写回先例
网关-->>你: 第二天早报：昨晚合并 18 个 PR、发版完成、无待办
```
